# ISO 9241-151:2008: historical web-interface guidance

Use when organizing web content, navigation, search, and presentation, or reviewing a claim based on this historical reference.

## Status and evidence boundary

[ISO 9241-151:2008](https://www.iso.org/standard/37031.html), edition 1, is **withdrawn**; ISO records withdrawal on **2 October 2018**. This guide does not infer a reason or successor from that status. It is a historical usability reference, not a current-standard or accessibility-conformance claim.

The catalog names four topic groups. The public [preview contents, page iii](https://cdn.standards.iteh.ai/samples/37031/2e884103228d464cb2d94e0f235385e8/ISO-9241-151-2008.pdf#page=3), assigns them to sections 6-9 and also lists section 10, **General design aspects**. Thus the four groups are not the entire document. The exact short group titles appear below; the implementation advice is our original application, not a reproduction of licensed clauses. Sources checked 2026-11-15; the full standard was not reviewed or bundled.

The original scope does not supply detailed implementation or artistic-design prescriptions and notes that mobile interfaces can need additional guidance. Use [WCAG](wcag-22.md) for accessibility, [ISO 9241-110](iso-9241-110.md) for current interaction principles, and [ISO 9241-112](iso-9241-112.md) for current information-presentation principles.

## 6. High-level design decisions and design strategy

- **Apply:** organize around user goals and tasks. Establish relevant skill levels, devices, inputs, connection limits, and language needs; test localization, text expansion, formats, and right-to-left reading where supported.
- **Example:** a task-oriented navigation label leads to a permission review regardless of which internal team owns the backend. A translated label can wrap without hiding its control.
- **Check:** run the same task across representative contexts and supported languages. Explain untested environments instead of claiming universal usability.

## 7. Content design

- **Apply:** group related information in a meaningful hierarchy, with concise text and useful headings. Split content when it helps comprehension or a task; avoid arbitrary pagination. Include media when it explains something the user needs, with appropriate accessible alternatives.
- **Example:** a permission detail view groups effective access, its source, and blocked-action reasons under descriptive headings rather than scattering them across unrelated tabs.
- **Check:** ask users to find and explain the answer, including from a heading outline. Check that condensed or hidden detail does not remove evidence needed for the decision.

## 8. Navigation and search

- **Apply:** make important paths direct and predictable without imposing a maximum click count. Use page titles, active navigation, and breadcrumbs where they help orientation. Write descriptive link text and preserve meaningful return paths. When search is useful, make it discoverable and accessible, with clear query, results, filters, and recovery from empty or mistaken queries.
- **Example:** search for an agent preserves the query and filter state when returning from its detail view. A misspelled query offers a suggestion without silently changing the search's meaning.
- **Check:** test a successful query, no results, a typo, keyboard operation, and return navigation. Evaluate result counts, visited/external-link indicators, and search placement for the task; a top-right search box or a particular breadcrumb format is not a rule established here.

## 9. Content presentation

- **Apply:** keep recurring elements in a consistent relative order while allowing responsive rearrangement. Use hierarchy, alignment, whitespace, and legible type to expose relationships. Give users control over disruptive media and overlays; avoid unexpected sound, unsolicited windows, or redirects that lose their place.
- **Example:** navigation precedes the main task on both wide and narrow views, without requiring identical pixel coordinates. A help video starts on request and has accessible controls.
- **Check:** inspect zoom, long labels, keyboard focus, media playback, and closing overlays. Confirm content and control remain usable. Use the [web design baseline](web-design-baseline.md) for optional typography starting points, not as ISO requirements.
